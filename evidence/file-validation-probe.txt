=== DEFECT FOUND (1 of 31) ===
  isPathTraversalSafe('/etc/passwd') -> true   (expected false)

  A POSIX-absolute path is accepted as safe. Cause: the function rejects
  '\\\\' (UNC) and '//', a drive letter, '~', encoded traversal and '.'/'..'
  segments, but never a SINGLE leading separator. For '/etc/passwd',
  split(/[\\/]+/) yields ['', 'etc', 'passwd'] - no '.'/'..' segment and a
  non-empty last segment - so it falls through to 'return true'.

  The asymmetry is the giveaway that this is an oversight, not a deliberate
  allowance: '//etc/passwd' IS rejected while '/etc/passwd' is not.

  Impact: a stored file_path is meant to be bucket-relative. If a consumer
  RESOLVES it instead of joining it - path.resolve('/bucket','/etc/passwd')
  yields '/etc/passwd', unlike path.join - the guarantee is gone. The value
  arrives from the client via the file-registration endpoint.

  Reported to the module's author with a suggested one-line fix
  (reject when the first split segment is empty). Re-run this probe after
  the fix to confirm 31/31.
