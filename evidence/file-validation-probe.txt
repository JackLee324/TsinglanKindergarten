################################################################
# A FALSE POSITIVE IN THIS PROBE, AND ITS CORRECTION
################################################################

The probe originally asserted isPathTraversalSafe('/etc/passwd') === false
and reported 30/31 with that as the one defect. THAT ASSERTION WAS WRONG,
and acting on it briefly introduced a real regression.

Evidence that it was wrong - the real shape of stored paths in this platform:
  server/database/seed-curriculum.sql / curriculum.data.ts contain
    "filePath": "/curriculum-resources/prek-english-covers/1876907126277273.jpg"
  i.e. platform bucket keys BEGIN with '/'. The value is passed to a
  bucket-scoped storage client and resolved against the BUCKET ROOT; it never
  touches a filesystem. An absolute-looking bucket key is therefore normal,
  not dangerous. What must be rejected is traversal ('..', '.'), UNC, drive
  letters, '~' and encoded traversal - all of which the module already did.

The module's OWN test suite (tests/file-security.test.mjs, written
independently by the module author) caught the regression: its case
'accepts ordinary stored paths' expects '/uploads/2024/lesson.pdf' to be
safe and started failing. The source change was reverted, and this probe's
assertion was corrected to encode the real convention.

This is recorded rather than quietly deleted: a probe that is itself
ungrounded produces confident, wrong findings, and the only reason it was
caught is that a second, independent test suite disagreed.
