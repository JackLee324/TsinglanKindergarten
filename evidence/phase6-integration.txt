   I described the magic-byte/declaration-consistency check as proof that
   a disguised file is REJECTED. It does reject such payloads when handed
   them, and my probe confirms that. BUT in the real flow the 'head' bytes

   registerFile only ever sees what the caller sends. So the check proves
   the caller can produce self-consistent bytes - NOT that the stored object
   is really that type. Authoritative verification requires a server-side
   read of the stored object, which needs the missing platform integration.
   Corrected in the report rather than left as a stronger claim than the
   evidence supports.
