=== THE 19 ROUTES WITHOUT AN EXPLICIT PERMISSION DECORATOR ===

These are NOT unauthenticated. AuthGuard AND PermissionGuard are both
registered as global APP_GUARD providers in server/modules/auth/auth.module.ts
(lines 26 and 30), in that order, so EVERY route requires an authenticated
session unless explicitly exempted. The 19 routes fall into four groups:

1) Auth self-service routes (act on the caller's OWN account) - correct:
     POST /api/auth/login            (necessarily unauthenticated)
     POST /api/auth/mfa/verify       (necessarily unauthenticated - 2nd factor)
     POST /api/auth/mfa/confirm
     POST /api/auth/mfa/disable
     POST /api/auth/mfa/recovery-codes
     POST /api/auth/change-password
     POST /api/auth/reset-password
     POST /api/auth/logout
   Granting these a permission would be wrong: every account must be able to
   change its own password and enrol its own MFA, including an account that
   currently holds no permission at all.

2) Dashboard routes - scoped to the caller, no cross-user read:
     GET /api/dashboard/stats   -> getStats(teacher.id)
     GET /api/dashboard/recent  -> getRecentUpdates(teacher.id, limit)
   Both pass the CALLER's id into the service, so they cannot return another
   account's data. Authenticated-only is defensible.

3) Curriculum read-only catalogue routes:
     GET /api/curriculum/structure | /folders | /roles
   Static catalogue data, no user data. Authenticated-only is defensible,
   though it would be better to declare it explicitly (see FINDING below).

4) FALSE POSITIVE in this scan:
     server/modules/hello/hello.controller.ts is ENTIRELY COMMENTED OUT
     (template sample code). The scanner matched commented source. There is
     no live /api/hello/test route.

=== FINDINGS ===

A-1 [LOW, defence in depth] dashboard and curriculum routes rely on
    authentication alone. No exploit exists (services are caller-scoped), but
    an explicit @RequirePermission('dashboard.view') / ('resource.view') would
    make the intent auditable and would survive a future refactor that
    forgets to scope by teacher id. RECOMMENDED, not a blocker.

A-2 [INFO] server/modules/hello/ contains dead template code. It is inert
    (fully commented), so it is not a vulnerability, but it should be deleted
    so that future static scans do not report phantom routes. This scan is
    itself the evidence that dead code creates audit noise.
