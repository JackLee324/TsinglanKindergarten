# V2 产品需求

> 一句话定义：**一个简单的教师资源平台** —— 教师在目录里找资源、传资源；
> 管理员管账号、管权限、管目录、审资源、看审计。
>
> 本文是需求基准。`ARCHITECTURE.md` / `DATA_MODEL.md` / `DIRECTORY_MODEL.md` /
> `PERMISSION_MODEL.md` / `RESOURCE_LIFECYCLE.md` 都是它的实现设计。

## 1. 两条主线

```
教师：  登录 → 目录 → 资源 → 上传 → 提交 → 查看 → 下载
管理员：账号 → 权限 → 目录 → 审核 → 审计
```

产品结构（一级导航）：

```
教师平台
├── 教育教学          ← 目录（管理员可增删改）
├── 教师成长          ← 目录（管理员可增删改）
├── 我的资源
├── 审核              ← 有审核权限的人可见
└── 管理              ← 只有 ADMIN 可见
```

**"教育教学"和"教师成长"不是代码里写死的一级栏目**，它们是 `directories` 表里
`parent_id IS NULL` 的两行数据。管理员可以再加"活动""班级""校历"，侧边栏自动出现。

## 2. 教师看到的与不看到的

| 教师**应该**看到 | 教师**不该**看到（全部属于后端实现） |
|---|---|
| 目录名（美德、教学资源…） | `directory id`、`slug`、`code` |
| 「上传资源」「新建文件夹」按钮（由目录能力决定） | 权限码（`resource.create`） |
| 资源列表、资源详情、文件预览、下载 | 存储 bucket、对象 key、签名 URL |
| 审核状态（草稿/待审核/已发布/已退回/已撤回） | session token、会话撤销记录 |
| 上传后所在目录的完整路径 | RBAC、Scope、Grant、Deny、Override |
| 退回原因 | MFA challenge（V2 第一阶段不做 MFA） |

**验收方式**：教师界面的 DOM 文本里不出现 `permission`、`scope`、`rbac`、
`directoryId`、`bucket`、`presign` 这类词（由浏览器测试断言）。

## 3. 管理员看到的

管理界面只回答四个问题：

1. **谁可以看什么？** —— 教师账号 → 勾权限 → 勾目录范围
2. **谁可以上传什么？** —— 同上
3. **这个目录里面有什么？** —— 目录管理树 + 资源清单
4. **发生了什么？** —— 审计日志

管理界面**不出现**：RBAC、Scope、Deny、Grant、Effective Permission、Role Ceiling。

## 4. 目录浏览（教师主界面）

**不要做成数据库树。** 沿用当前 V1「美德」页面的视觉语言：卡片 + 标题 + 数量 + 简介 + 进入箭头。

```
Pre-K
[ 美德 ]  [ 蒙特梭利 ]  [ 体能 ]  [ 英文 ]
     ↓ 点击「美德」
美德
[ 课程大纲 ]  [ 教学详案 ]  [ 教学资源 ]  [ 考核评估 ]
     ↓ 点击「教学资源」
资源列表（卡片/列表 + 搜索 + 筛选 + 分页）
```

面包屑显示完整路径：`教育教学 / Pre-K / 美德 / 教学资源`。

## 5. 上传（教师最常用的动作）

**从目录页进入，不是从一个空白的上传页进入。**

```
教育教学 / Pre-K / 美德 / 教学资源      ← 从目录页点「上传资源」
                                        （此时 directoryId 已经确定）

  标题   [ ________________ ]
  描述   [ ________________ ]
  文件   [ 选择文件 ]  教学详案.pdf  2.3 MB   ✔ 已上传
  [ 保存草稿 ]
```

**界面上不出现**：班型、科目、legacy 资料夹类型、目录选择。

上传成功后必须显示：

```
✔ 上传成功
  文件：教学详案.pdf（2.3 MB）
  位置：教育教学 / Pre-K / 美德 / 教学资源
  状态：已上传
```

刷新页面后，从该目录仍然能找到这条资源。

一个资源可以有多个文件（教案.pdf + 课件.pptx + 工作单.docx）：
界面用 **[ + 添加文件 ]** 逐个添加，**不做批量多文件上传界面**。

## 6. 目录扩展（V2 真正完成的标志）

管理员在管理界面里：

```
新增一级栏目：活动
  → 刷新网页 → 侧边栏出现「活动」
  → 新增子目录：2027 春季活动 → 刷新 → 仍在
  → 新增子目录：春游 / 六一 / 毕业典礼 → 刷新 → 仍在
```

同一套能力也用于：

```
班级           校历              教研
├── K1         └── 2027          └── 2027 春季
├── K2             ├── 学期安排
└── K3             ├── 节假日
                   └── 学校活动
```

**全程不需要：改 React、改 route、改代码、重新发布。**

## 8. 权限（管理员看到的样子）

不给管理员看权限码。只有勾选框：

```
☑ 查看资源      ☑ 上传资源     ☑ 编辑自己的资源   ☑ 下载资源
☐ 提交审核      ☐ 审核资源     ☐ 发布资源
☐ 管理目录      ☐ 管理教师     ☐ 查看审计
```

然后勾**开放范围**（一棵目录树，勾父节点等于包含子树）：

```
☑ 教育教学
    ☑ Pre-K
        ☑ 美德
        ☐ 蒙特梭利
        ☐ 体能
        ☐ 英文
    ☐ K
☐ 教师成长
```

保存即完成。背后是一次 `PUT /api/users/:id/permissions`。

**没有** deny、grant、override、role ceiling、多套 Scope 形态。

**不出现在这个表单里，也不出现在任何提示里**。

## 10. 资源与文件

| 能力 | 要求 |
|---|---|
| 搜索 | 标题、描述、文件名、目录名 |
| 筛选 | 目录、状态、班型（若目录结构中存在对应的层级） |
| 分页 | **不允许固定只显示 50 条**；分页或"加载更多"，且显示总数 |
| 预览 | PDF / JPG / PNG / TXT 网页内预览 |
| 下载 | 一切类型都可下载；DOCX/XLSX/PPTX/ZIP 只提供下载 |
| 不支持预览时 | 明确显示「此文件类型暂不支持在线预览，请下载查看」 |
| 禁止 | 点击后无反应；"开发中"；"Coming Soon" |

## 11. 我的资源

必备操作：查看、详情、编辑、保存草稿、提交审核、查看退回原因、重新提交、
删除、恢复、查看文件、预览、下载。

分栏：全部 / 草稿 / 待审核 / 已发布 / 已退回 / 已撤回 / 回收站。

## 12. 审核

审核页三栏：待审核 / 已通过 / 已退回。操作：查看、通过、退回（**退回必须填原因**）。

已发布资源可以**撤回**，撤回走独立的撤回动作，**不能调用 reject**。

## 13. 状态机

```
DRAFT ──提交──> PENDING_REVIEW ──通过──> PUBLISHED ──撤回──> RECALLED
                     │                                          │
                     └──退回──> REJECTED ──编辑──> DRAFT <──────┘

active ──删除──> recycle ──恢复──> active
                     └──永久删除──> （数据库 + 文件 + 审计，三者都必须真的发生）
```

每一次状态变化必须同时落到：数据库、界面、审计。

## 14. 审计（只记有用的）

登录、账号创建、账号修改、账号停用、权限修改、目录新增、目录修改、目录删除、
资源上传、资源编辑、提交审核、通过、退回、发布、撤回、删除、恢复、永久删除、下载。

**不记录**：密码、Session token、对象存储密钥。

## 15. 明确不做（避免误解）

| 不做 | 归属 |
|---|---|
| MFA / 验证码 / 恢复码 | FUTURE |
| 企业微信登录 | FUTURE |
| 复杂通知系统 | FUTURE |
| 完整版本树 / 复杂版本管理 | FUTURE（先做"已发布不可直接覆盖"） |
| 高级统计与图表仪表盘 | FUTURE |
| 数据库层 RLS | 不做（应用层强制 + 如实写进已知限制） |
| 批量多文件上传界面 | 不做（模型支持多文件，界面逐个添加） |
| 第二套组件库 / 平台兼容层 | 不做 |

## 16. 成功标准（业主原话的落地）

> 管理员新增「活动」→ 刷新 → 侧边栏自动出现「活动」。
> 点进去新增「2027 春季活动」→ 刷新 → 仍在。
> 再新增「春游」→ 刷新 → 仍在。
> **无需改 React、改 route、改代码、重新发布。**

这就是 V2 Directory 真正完成的标志，也是阶段 3 的验收项。

## 17. 最终目标（一句话）

用户只需要理解：**"我在哪个目录？""我要上传什么？""我要看什么？""我要下载什么？"**

管理员只需要理解：**"谁可以看什么？""谁可以上传什么？""这个目录里面有什么？"**

不需要任何人理解：RBAC、Scope、Token、Permission override、legacy folder、
storage bucket、directory id、session challenge。
