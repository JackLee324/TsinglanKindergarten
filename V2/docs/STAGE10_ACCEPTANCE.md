# V2 全业务浏览器验收（阶段 10）

> 业主 Stage 10 的目标：**对整个 V2 做一次真实业务全链路验收**。
> 不是接口测试，不是"页面打得开"，而是用真实浏览器扮演一位管理员和两位老师，
> 把业主列的 22 节逐条走一遍。
>
> 判据用的是业主自己给的那条硬规则：
> **功能完成 = UI 有入口 + 用户可以点击 + API 存在 + 后端逻辑存在 + 数据库真的改变
> + 刷新后状态还在 + 权限正确 + 异常正确 + 浏览器真实通过。少任何一项都叫 INCOMPLETE。**

验收脚本：`tests/integration/browser.stage10.test.mjs`（42 条，CDP 驱动真实 Chrome）。
全程采集 console 与网络（CDP 的 `Runtime` / `Log` / `Network` 三个域）。

## 2. 本阶段**发现并补齐**的两处 INCOMPLETE

用业主那条硬规则逐项核对时，有两处是"后端有、界面没有" —— 按规则算 INCOMPLETE，
而它们正好都落在业主 §1 / §13 / §14 / §5 要求跑通的链路上，所以本阶段补齐后再验收：

### （一）删除 / 回收站 / 恢复：接口齐全，界面一条都没有

`DELETE /api/resources/:id`（软删除）、`POST /api/resources/:id/restore`、
`GET /api/resources/{mine/,}recycle-bin` 在阶段 5 就有，**但客户端连 API 函数都没写**，
「我的资源」的六栏里也没有回收站。于是业主 §1 的"…→ 删除 → 恢复"和
§14 的"删除：进入回收站。恢复：重新出现"**在界面上走不通**。

补齐（客户端，服务端未改一行）：

* `client/src/api/resources.ts`：`remove` / `restore` / `recycleBin` / `allRecycleBin`；
* `shared/resource-query.ts`：`MY_RESOURCE_TABS` 增加第七栏「回收站」
  （带 `recycle: true` 标记 —— 它不是状态，走的是按 `deleted_at` 取的另一条路）；
* 「我的资源 → 回收站」：列出已删除资源 + 「恢复」按钮；
  管理员走 `/recycle-bin`（看**全部人**的），教师走 `/mine/recycle-bin`（只看自己的）——
  范围由服务端决定，界面不自己过滤；
* 资源详情页新增「删除」（带确认弹窗，说明"会进回收站，可以恢复"）。
  **没有**做"彻底删除" —— 业主在阶段 8 明确不要 purge 界面。

### （二）教师自建文件夹：同样只有接口

`POST /api/directories/folders` + 客户端 `directoriesApi.createFolder` 都在，
但目录浏览页没有任何入口，业主 §5「在教学资源创建『环境创设』」无法完成。

补齐：目录浏览页在**服务端说可以**（`capabilities.canCreateFolder`）时显示「新建文件夹」，
新建弹窗只问名称与英文/拼音名，建完直接进去。

顺带修掉一个会让人卡住的真实问题：**中文名生成不出可读地址**
（服务端的 `slugifyCandidate` 对纯中文返回空，会回一句英文报错）。
现在弹窗在**提交之前**就说清"请再填一个英文/拼音名称：文件夹的地址由它生成"，
而不是等老师点完创建再看服务端的报错。

| 节 | 要求 | 怎么验的（要点） |
|---|---|---|
| ① | 完整业务链 | 管理员**在界面上**建老师并授权 → 老师登录 → 点进 美德/教学资源 → 上传 PDF → 草稿落库 → 刷新仍在 → 详情/预览/下载（sha256 一致）→ 提交 → 管理员**通过并发布** → 老师回目录**找得到** → 下载 → 删除 → 恢复 |

| ⑥ | 八种类型真实上传 | PDF / JPG / PNG / TXT / DOCX / XLSX / PPTX / ZIP 各传一次；每个都回库核对 `file_name` / `size` / `sha256` |
| ⑦ | 保存后刷新 | 八条草稿刷新后都在，状态是 `DRAFT` |

| ⑫ | 权限边界 | 侧边栏没有未授权目录；直接开地址被回退并说明原因；接口 `?directoryId=<未授权>` → **403**；往未授权目录建资源 → **403** |

## 4. Safari：为什么是 UNVERIFIED（不是"跑过了"）

`safaridriver` 在机器上是有的（Safari 26.6），但**建会话被系统拒绝**：

```
Could not create a session: You must enable 'Allow remote automation'
in the Developer section of Safari Settings to control Safari via WebDriver.
```

这是 Apple 的**一次性人工开关**，自动化打不开：

* `safaridriver --enable` 会要**管理员密码**（本机试过：`Password is not valid`）；
* 直接写 Safari 的偏好也不行（Safari 的容器有沙箱：
  `Could not write domain …/Containers/com.apple.Safari/…`）。

所以本阶段**没有**把 Safari 那一遍算作通过。已经准备好的是"打开开关就能跑"：

```bash
# 0) Safari → 设置 → 开发者 → 勾选「允许远程自动化」
#    （没有「开发者」菜单：Safari → 设置 → 高级 → 显示网页开发者功能）
# 1) 让服务跑起来（例如 npm test 会起 3311，或已部署的地址）
safaridriver -p 4444
# 2) 真实 Safari 跑关键路径：登录 → 教育教学 → Pre-K → 美德 → 教学资源 → 资源详情
npm run verify:safari -- --base http://127.0.0.1:3311 \
  --user s10_teacher_a --pass 'S10TeacherA!1' --shot /tmp/safari-stage10.png
```

`tests/helpers/safari.mjs`（零依赖的 W3C WebDriver 客户端）+ `scripts/verify-safari.mjs`
已经写好并验证过**失败路径**：开关没打开时它打印照做即可的两步说明并以退出码 2 结束，
**不会**假装通过。开关打开后同一条命令会走完关键路径并留下截图。

> 为什么坚持要第二种引擎：Safari 与 Chromium 在 `SameSite` Cookie、`HttpOnly`、
> fetch 缓存、PDF 内联预览上都有差异，而这类差异**只会在另一种引擎上暴露**。
> 阶段 11（手机端）会再遇到一次同样的问题（iPhone 上是 WebKit）。

## 5. 422 / 429：这两个码在 V2 里不存在（如实说明，不造假）

业主 §18 要求"真实制造 401/403/404/409/422/429"。前四个已真实制造（见 §3 ⑱）。
后两个**造不出来**，因为它们是设计上不存在的：

* **422**：V2 的入参校验一律回 **400 + 机器可读的 `code`**（class-validator + 统一错误体），
  没有"语法对、语义错用 422"这一层。用例里钉住的是这条真实契约。
* **429**：V2 **没有实现限流**（全仓没有任何产出 429 的代码）。
  用例里如实记录了"连续 5 次登录失败也都是 401，没有 429"。
  限流属于部署层（Nginx / Caddy），是**阶段 12** 的课题 —— 业主在 §18 里也把 429
  列进了"阶段 12 要能看到的东西"。

与其伪造一个 422/429，不如把真实发生的事写下来。这是本阶段唯一一处
"要求的东西不存在"，也是唯一需要在生产验收前补的一课。
