# V2 全业务浏览器验收（阶段 10）

> 业主 Stage 10 的目标：**对整个 V2 做一次真实业务全链路验收**。
> 不是接口测试，不是"页面打得开"，而是用真实浏览器扮演一位管理员和两位老师，
> 把业主列的 22 节逐条走一遍。
>
> 判据用的是业主自己给的那条硬规则：
> **功能完成 = UI 有入口 + 用户可以点击 + API 存在 + 后端逻辑存在 + 数据库真的改变
> + 刷新后状态还在 + 权限正确 + 异常正确 + 浏览器真实通过。少任何一项都叫 INCOMPLETE。**

验收脚本：`tests/integration/browser.stage10.test.mjs`（42 条，CDP 驱动真实 Chrome）。
全程采集 console 与网络（CDP 的 `Runtime` / `Log` / `Network` 三个域）。

## 2. 本阶段**发现并补齐**的两处 INCOMPLETE

用业主那条硬规则逐项核对时，有两处是"后端有、界面没有" —— 按规则算 INCOMPLETE，
而它们正好都落在业主 §1 / §13 / §14 / §5 要求跑通的链路上，所以本阶段补齐后再验收：

### （一）删除 / 回收站 / 恢复：接口齐全，界面一条都没有

`DELETE /api/resources/:id`（软删除）、`POST /api/resources/:id/restore`、
`GET /api/resources/{mine/,}recycle-bin` 在阶段 5 就有，**但客户端连 API 函数都没写**，
「我的资源」的六栏里也没有回收站。于是业主 §1 的"…→ 删除 → 恢复"和
§14 的"删除：进入回收站。恢复：重新出现"**在界面上走不通**。

补齐（客户端，服务端未改一行）：

* `client/src/api/resources.ts`：`remove` / `restore` / `recycleBin` / `allRecycleBin`；
* `shared/resource-query.ts`：`MY_RESOURCE_TABS` 增加第七栏「回收站」
  （带 `recycle: true` 标记 —— 它不是状态，走的是按 `deleted_at` 取的另一条路）；
* 「我的资源 → 回收站」：列出已删除资源 + 「恢复」按钮；
  管理员走 `/recycle-bin`（看**全部人**的），教师走 `/mine/recycle-bin`（只看自己的）——
  范围由服务端决定，界面不自己过滤；
* 资源详情页新增「删除」（带确认弹窗，说明"会进回收站，可以恢复"）。
  **没有**做"彻底删除" —— 业主在阶段 8 明确不要 purge 界面。

### （二）教师自建文件夹：同样只有接口

`POST /api/directories/folders` + 客户端 `directoriesApi.createFolder` 都在，
但目录浏览页没有任何入口，业主 §5「在教学资源创建『环境创设』」无法完成。

补齐：目录浏览页在**服务端说可以**（`capabilities.canCreateFolder`）时显示「新建文件夹」，
新建弹窗只问名称与英文/拼音名，建完直接进去。

顺带修掉一个会让人卡住的真实问题：**中文名生成不出可读地址**
（服务端的 `slugifyCandidate` 对纯中文返回空，会回一句英文报错）。
现在弹窗在**提交之前**就说清"请再填一个英文/拼音名称：文件夹的地址由它生成"，
而不是等老师点完创建再看服务端的报错。

## 3. 22 节逐条对照

| 节 | 要求 | 怎么验的（要点） |
|---|---|---|
| ① | 完整业务链 | 管理员**在界面上**建老师并授权 → 老师登录 → 点进 美德/教学资源 → 上传 PDF → 草稿落库 → 刷新仍在 → 详情/预览/下载（sha256 一致）→ 提交 → 管理员**通过并发布** → 老师回目录**找得到** → 下载 → 删除 → 恢复 |
| ② | 目录靠点击 | 教育教学→Pre-K→美德→四个资料夹逐个点进去（每次都断言 `data-directory-path`）；教师成长→L1→安全施教规范→应急预案→传染病识别与防治。**不输 URL** |
| ③ | 改目录名四处同步、slug 不变 | 美德→美德课程：侧边栏 / Pre-K 页 / 目录页标题 / 详情页面包屑全部同步；`slug` 仍是 `virtue`、地址仍是 `…/virtue` |

| ⑤ | 自建文件夹 | 教学资源下建「环境创设」→ 刷新仍在 → 进去上传 → 资源的 `directory_id` 就是它 |
| ⑥ | 八种类型真实上传 | PDF / JPG / PNG / TXT / DOCX / XLSX / PPTX / ZIP 各传一次；每个都回库核对 `file_name` / `size` / `sha256` |
| ⑦ | 保存后刷新 | 八条草稿刷新后都在，状态是 `DRAFT` |
| ⑧ | 预览 | PDF：iframe + 签名地址；图片：`img.complete && naturalWidth > 0`（**真的解码成功**，不是有个 `<img>` 标签）；TXT：内容真的渲染出来；DOCX/XLSX/PPTX/ZIP：**没有**预览按钮，逐字显示「此文件类型暂不支持在线预览，请下载查看。」且可下载 |
| ⑨ | 下载 sha256 | 八种类型逐个下载，与上传字节逐字节一致 |
| ⑩ | 审核 | 提交→待审核；不写原因**退不回去**（界面拦住）；写了原因→已退回；老师在卡片与审核记录里都看得到原因；编辑→回到草稿→重新提交 |
| ⑪ | 撤回 | `published → recalled`；目录列表里消失，我的资源「已撤回」里仍在 |
| ⑫ | 权限边界 | 侧边栏没有未授权目录；直接开地址被回退并说明原因；接口 `?directoryId=<未授权>` → **403**；往未授权目录建资源 → **403** |
| ⑬ | Session | 改权限后旧会话立刻失效（浏览器被送回登录页）；停用后旧会话失效且**登不回来**（有明确提示）；重新登录后新权限（K）生效 |
| ⑭ | 回收站 | 删除是软删除（`deleted_at` 写上、文件行还在、审计留痕）；「回收站」里恢复→`deleted_at` 清空、回到原目录；发布后原目录里重新出现；**管理员看得到别人删的** |

## 4. Safari Desktop：**真 Safari 已跑通**（第二引擎）

业主 §20 要求 Safari 也跑一次，并在 §"一"里给出了这一遍必须覆盖的步骤。
脚本：`tests/safari/acceptance.safari.test.mjs`（W3C WebDriver，零依赖，
`tests/helpers/safari.mjs` 自己实现 —— 没有引入 Playwright）。
命令：`safaridriver -p 4444` 然后 `npm run test:safari`。

### 4.1 结果：10/10 通过，9 个业务步骤全部 PASS

| 步骤 | 结果 | 验的是什么 |
|---|---|---|
| 打开登录页并登录 | **PASS** | Safari 里的真实表单提交（`SameSite`/`HttpOnly` Cookie 在 WebKit 上照常工作） |
| 一格格点进 教学资源 | **PASS** | 教育教学 → Pre-K → 美德 → 教学资源，每一步都核对 `data-directory-path` |
| 点开资源详情 | **PASS** | 列表 → 详情页，标题一致 |
| PDF 预览 | **PASS** | iframe + 签名地址；并且**让 Safari 自己去请求那个地址**，核对 `200` / `application/pdf` / 字节数 |
| 图片预览 | **PASS** | `img.complete && naturalWidth > 0 && naturalHeight > 0` —— Safari 真的解码出来了 |
| 下载 | **PASS** | 点下载 → 服务端 `resource.download` 审计落库（target 是**文件 id**）→ Safari 取回字节并算 sha256，与上传逐字节一致，且响应带 `Content-Disposition: attachment` |
| 我的资源 → 提交审核 | **PASS** | 草稿提交后库里变成 `PENDING_REVIEW` |
| 管理员审核 → 通过并发布 | **PASS** | 同一个 Safari 窗口里换账号登录（退出→登录），点「通过并发布」，库里变成 `PUBLISHED` |
| 撤回 → 删除 → 回收站 → 恢复 | **PASS** | `published → recall → 删除（软删）→ 回收站恢复`，每一步都回库核对 `status` / `deleted_at` |

**关于点击**：这一遍的 100% 点击都走 **WebDriver 标准点击（含 Safari 自己的命中测试）**，
没有一处退回"页面内 click"。这一点是逐条核对的：驱动在设置不可交互时才会退，
而这次一次都没退。

**关于下载**：浏览器的下载会落进**用户自己的**下载目录，我们不去翻人家的目录；
所以字节核对用的是"应用自己申请的签名地址 + Safari 去取"，再叠加服务端审计，
两条独立证据合起来证明这次下载真的发生了。

### 4.2 Safari 比 Chrome 多做了一件事：它抓出一个真问题

第一次跑 Safari 时，侧边栏的 6 个导航项全部被判 `element not interactable`，
命中测试显示 **尺寸 0×0**。于是量了一遍（Safari 实测）：

| 视口宽 | 侧边栏宽 | 可见导航项 | 汉堡/抽屉按钮 |
|---:|---:|---:|---:|
| 1440px | 240px | 9 | 0 |
| 1200px | 240px | 9 | 0 |
| **1023px** | **0px** | **0** | **0** |
| 900px | 0px | 0 | 0 |
| 390px | 0px | 0 | 0 |

**结论：视口窄于 1024px 时，整个站点没有任何导航入口。**
侧边栏是 `hidden … lg:flex`，而 **没有**汉堡菜单、也没有底部导航
（`Layout.tsx` 里除了 `lg:pl-60` 没有任何窄屏分支）。
也就是说：**在手机上，老师只能靠输地址来进目录** —— 这正是阶段 11 要解决的问题，
本阶段**只记录、不顺手加功能**（业主的 Stage 11 明确说"不要重新设计 UI，只修响应式"）。

桌面端 Safari 这一遍因此先把窗口设成 1440×900（业主要的就是 "Safari desktop"），
并把这个前提**写在测试里**（`setWindowRect` 的注释），避免以后有人把视口问题当成业务问题。

### 4.3 前提：Safari 的一次性开关

`safaridriver` 建会话需要系统级的一次性开关（自动化打不开它）：

* Safari → 设置 → 开发者 → 勾选「允许远程自动化」
  （没有「开发者」菜单：设置 → 高级 → 显示网页开发者功能）；
* 或 `safaridriver --enable`（要管理员密码）。

没有打开时 `npm run test:safari` 会**红在第一句**，报错信息就是上面这两步 ——
它不会跳过、也不会假装通过。**业主已打开此开关，本节结果是在打开之后跑出来的真结果。**

## 5. 422 / 429：这两个码在 V2 里不存在（如实说明，不造假）

业主 §18 要求"真实制造 401/403/404/409/422/429"。前四个已真实制造（见 §3 ⑱）。
后两个**造不出来**，因为它们是设计上不存在的：

* **422**：**V2 的 API 校验用 400**（class-validator + 统一错误体，带机器可读的 `code`），
  没有"语法对、语义错用 422"这一层。用例里钉住的是这条真实契约。
  **不会为了凑状态码去加 422。**
* **429**：**限流属于阶段 12 的反向代理**（Nginx / Caddy），本阶段**不在业务层加限流**。
  V2 目前没有实现限流（全仓没有任何产出 429 的代码），用例里如实记录了
  "连续 5 次登录失败也都是 401，没有 429"；阶段 12 会在代理层产生并观测 429。

与其伪造一个 422/429，不如把真实发生的事写下来。这是本阶段唯一一处
"要求的东西不存在"，也是唯一需要在生产验收前补的一课。

## 6. 复现方式

```bash
cd V2
export V2_TEST_DATABASE_URL='postgresql://qlsadmin:qlsdev_local_only@127.0.0.1:55432/qls_v2_test'

# ① Chrome：42 条业务验收（约 4 分钟）

```

跑完不留数据。
