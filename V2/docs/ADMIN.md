# V2 管理员（阶段 8）

> 这份文档回答两个问题：**管理员到底要管哪四件事**，
> 以及**为什么界面上只出现中文、不出现 RBAC 术语**。

## 1. 四件事，不是一套权限系统

```
管理
├── 教师账号   给老师开账号、改姓名、重置密码、启用/停用
├── 权限       勾"能做什么" + 勾"开放目录"
├── 目录       新增一级栏目 / 子目录、改名、排序、启停、删除保护
└── 审计       谁在什么时候做了什么、结果如何
```

业主的原话是：

> 管理员应该感觉"我就是在管理老师和目录"，
> 而不是"我在配置一个复杂的 RBAC 系统"。

所以界面上**不允许出现**这些词：`permission code`、`scope`、`grant`、`deny`、
`override`、`effective`、`role ceiling`、`permission version`。
有一条浏览器用例直接对整个管理界面做反向断言（出现这些词就红）。

对应地，数据模型也没有这些概念：

```
user_permissions (user_id, permission, directory_id)
```

一行业务含义 = "这位老师，在这个目录（含子树）上，能做这件事"。
`directory_id IS NULL` 表示全平台（只有 `user.manage` / `audit.view` 会用）。
**没有** deny、没有 override、没有权限版本、没有角色等级。

## 2. 身份只有两个

| 身份 | 能力 |
|---|---|
| `ADMIN` | 自动拥有全部系统能力（不需要给他配权限） |
| `TEACHER` | 由 `user_permissions` 决定 |

没有 `principal` / `director` / `specialist` / `assistant` 这些业务角色。
V1 那套角色体系**不回来**。

管理员的"自动拥有"只有一处实现：`AuthorizationService.can()` 里的 ADMIN 绕过。
Controller 与页面里都不允许出现 `role === 'ADMIN'`
（静态测试 `single-permission-truth` / `route-declarations` 会拦）。

## 3. 权限编辑器：为什么有"统一"和"分别设置"两种模式

界面默认是**统一开放目录**：

```
权限
☑ 查看资源   ☑ 上传资源   ☑ 编辑自己的资源   ☑ 下载资源
开放目录
☑ Pre-K → ☑ 美德 / ☑ 蒙特梭利
```

= 这四个权限都在"美德 + 蒙特梭利"上生效。

但数据模型是 `(permission, directoryId)` 的**组合**，所以"查看 Pre-K 全部、
只在美德能上传"这种配置是合法的。如果界面只给"统一"模式，
打开一个已经这么配过的老师、再点保存，就会把他那些不一样的授权
**悄悄抹平成一个笛卡尔积**。

所以编辑器先检测：不是笛卡尔积 → 自动进入**分别设置**并说明原因。
宁可多一个模式，也不要静默改掉别人的权限。

保存时写的是**整份替换**（`PUT`），不是增量 —— 界面上勾选框提交的就是最终结果。
增量接口会让"取消勾选"变成一次删除的猜测。

### 3.1 「我什么都没改，只是点了保存」必须成立

这一条是被浏览器用例逼出来的，两个缺陷都是**打开页面什么都不改**才暴露的：

| 现象 | 原因 | 现在怎么保证 |
|---|---|---|
| 点保存报「请求参数不合法」 | 读接口的授权项比提交的多一个 `label`（界面要显示中文名），原样发回去被服务端白名单拒掉 | `adminApi.setPermissions` 统一只提交 `{ permission, directoryId }`；类型上把 `PermissionItem`（读）与 `PermissionGrant`（写）分开 |
| 上面写着"当前方式：统一开放目录"，编辑器里却高亮着「分别设置」 | 底部那行读的是页面的猜测值，而方式其实由编辑器决定 | 编辑器通过 `onModeChange` 回传它**实际**在用的方式 |

两条都有浏览器用例守着（`tests/integration/browser.stage8.test.mjs` 的 ⑦）：
建一位"查看只管美德、上传只管蒙特梭利"的老师 → 打开 → **一个字都不改** →
保存 → 回数据库核对还是那 2 条授权（笛卡尔积会是 4 条）。

## 4. 改权限 = 立刻踢下线

任何一次 `PUT /permissions` 都会撤销该账号的**全部会话**。

理由：权限判断发生在服务端，如果旧会话继续有效，
"我刚把权限收回去了，他怎么还能看？"这个疑问就会出现。
所以保存成功的响应里带 `revokedSessions`，界面上会说
「权限已保存。该账号的登录状态已失效，需要重新登录后生效。」

同理，**停用账号**与**重置密码**也会撤销全部会话（以及"启用"——
因为重新启用时权限可能已经变了）。

> 这条在测试里踩过一次：写用例时改了某人的状态，却忘了自己的会话也会被撤销，
> 后面所有请求都变成 401，看起来像"接口坏了"。测试里为此专门有个 `relogin()` 辅助函数。

## 5. 两条护栏：不要让系统失去管理员

| 规则 | 结果 | 提示 |
|---|---|---|
| 停用 / 降级**最后一个** active 管理员 | 400 `LAST_ADMIN` | 「系统至少需要一名管理员。」 |
| 修改**自己**的身份 | 400 `SELF_ROLE_CHANGE` | 「不能修改自己的身份。需要交接时请让另一位管理员来改。」 |

第一条的理由：一旦没有管理员，界面上再也加不回来（唯一的路是直接改数据库）。
第二条的理由：自己降级是把自己锁在系统外最快的方式，而且通常是一次误操作。

**管理员也不能审核自己上传的资源**（阶段 7）——自审保护不看角色。

## 6. 停用，不删除

没有删除账号的接口（有一條用例专门断言 `DELETE /api/users/:id` 是 404）。

理由：审计日志、审核记录、资源的上传者都指向这个账号。
删掉他会让历史断链 —— 一条 2024 年的资源突然显示"上传者未知"，
而没人能解释为什么。停用的人仍然在列表里，可以再启用。

`users.status` 只有两个值：`active` / `inactive`。

## 7. 审计（§14 / §15）

界面上是筛选 + 列表，**不做统计聚合**（业主明确说"不要先做复杂统计"）：

* 按**动作**、按**结果**、按**操作者**、按**对象**、按**时间区间**；
* 每一条显示：时间 / 操作者 / 动作（中文标签）/ 对象 / 结果。

一个请求如果同时做了几件事（比如同时改了姓名和口令），会**分别记几条**：

```
user.password_change  管理员重置密码
user.disable          账号停用
user.update           账号修改
```

为什么不用"一条记录 + changed 字段"：审计最常见的用法就是**按动作筛选**
（"谁改过别人的密码？"）。如果改密码被记成 `user.update`，那个筛选就查不出来。

`directory.enable` / `directory.disable` 同理单独记 ——
某天某个目录对老师们"消失"了，你要能直接筛出来是谁关的。

审计里**绝不出现**：口令、password_hash、令牌、存储密钥、签名 URL
（`AUDIT_FORBIDDEN_DETAIL_KEYS` + 用例断言）。

> 业主 §15 的清单里写的 `permission.update` 在实现里叫 `user.permissions.update`
> （阶段 2 起就是这个名字，界面标签「权限修改」）。同一件事，没有第二个名字。

## 8. 界面上没有的东西（刻意不做）

* **MFA / 二次验证**：业主明确说"不要把 MFA 又加回来"。老师登录就是账号 + 密码。
* **通知**（邮件 / 站内信）、**统计报表**、**复杂版本对比**、**批量导入教师**。
* 删除账号、给管理员配权限（管理员不需要权限）、"指定另一个管理员"这种授权功能
  —— 系统保持一个最高管理员角色，交接靠另一位管理员改身份。

## 9. 测试怎么证明

| 套件 | 证明什么 |
|---|---|
| `tests/integration/admin-users.integration.test.mjs` | 搜索/分页/最后登录/权限摘要（不含权限码）、新增、停用不删除、无删除接口 |
| `tests/integration/admin-security.test.mjs` | 最后一个管理员保护、不能改自己身份、改权限/状态/口令即撤销会话、历史不断链、普通教师碰不了管理接口 |
| `tests/integration/admin-audit.test.mjs` | §15 的每个动作都会被记、§14 的四种筛选、筛选后 total 一致、凭据禁区 |
| `tests/integration/browser.stage8.test.mjs` | 真浏览器：开账号 → 登录 → 只在授权目录可见可上传 → K 目录 403 → 加权限后旧会话失效 → 重新登录生效 → 撤销权限 → 最后一个管理员不能停用（**并显示业主指定的那句话**）→ 目录三级链路（活动 → 2027 春季活动 → 春游）刷新后一级都不少、层级没被拍平、删除保护有效 → 审计查得到操作者/动作/目标/时间/结果 → 「打开后一字不改就保存」不扩大授权；外加"界面里不出现 RBAC 术语"的反向断言 |

## 10. 权限与"开放目录"的对应关系（§24）

界面上勾「Pre-K / 美德」+「查看资源」，数据库里就必须是：

```
user_permissions (user_id, 'resource.view', <美德目录的 id>)
```

不是某种"范围对象"，也不是一行 JSON。浏览器用例直接查库核对这一点。
