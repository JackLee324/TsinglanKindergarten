# V2 目录模型

> 这是 V2 的核心。业主的原话：
> **"Directory 必须成为整个网页课程导航的唯一真相。"**
> 以及："以后要加 活动 / 班级 / 校历 / 教研 / 培训 / 会议，
> 管理员点一下『新增一级目录』就可以了，**不需要 Agent 再写一个 `ActivitiesPage.tsx`**。"

## 1. 为什么是"通用树"而不是"课程树"

V1 的 `directories` 表带 `program` / `subject` / `sub_subject` / `is_system` 四个列。
它们把树锁定在"班型 → 科目 → 资料夹"这一种形状上，后果是：

- 想加一个不属于"班型/科目"的栏目（例如"活动""校历"），**必须新增代码路径**；
- 子科目与资料夹后缀会共用一个 code 段（`arts_resource`），解析归属时既当子科目又当后缀，
  实测造成 16 个文件夹拒绝所有上传；
- "系统节点不可改名"被写进服务层，导致管理员**在界面上根本没有改名按钮**（业主要求必须能改）。

V2 的做法：**树只有一个结构事实 `parent_id`，行为由每个节点自己的能力开关决定。**

## 2. 节点字段的语义

| 字段 | 可编辑 | 说明 |
|---|---|---|
| `id` | ✗ | 主键。资源与权限都指向它，**永不改变** |
| `parent_id` | 管理员可"移动" | 树的唯一结构事实。`NULL` = 一级栏目 |
| `slug` | 创建时可指定，之后**不可改** | 同级唯一；URL 用它。改名不动 slug → 链接永久有效 |
| `name` | ✓ | 中文名。侧边栏/首页/面包屑/上传页/资源详情读的都是它 |
| `name_en` | ✓ | 英文界面读它（V1 有 `name_en` 但界面一度够不着，V2 必须可直接编辑） |
| `description` | ✓ | 目录说明，可留空（空 → 存 `NULL`，不是空串） |
| `type` | ✓ | `ROOT` / `CATEGORY` / `SECTION` / `FOLDER`，**仅影响展示**（缩进、图标、默认文案） |
| `sort_order` | ✓ | 同级排序；↑↓ 交换相邻两行的值 |
| `enabled` | ✓ | 停用后该节点**及其整棵子树**对非管理员不可见 |
| `allow_children` | ✓ | 是否允许在其下建子目录 |
| `allow_files` | ✓ | 是否允许直接放资源（决定"上传资源"按钮出不出现） |
| `allow_custom_folders` | ✓ | 是否允许**普通教师**自建子文件夹 |
| `icon` | ✓ | 可选图标名 |

### 关键约定：**没有任何业务规则可以按 `type` 分支**

`type` 只是给人看的标签。决定行为的一律是：
`parent_id`（结构）、`enabled`（可见）、`allow_*`（能力）。

> 如果将来发现有地方写了 `if (node.type === 'SECTION')` 才允许某事，那是设计错误 ——
> 正确的做法是加一个能力开关。**这条由 `tests/directory-capabilities.test.mjs` 静态保证。**

## 3. 能力开关决定界面（而不是角色硬编码）

| 场景 | 判定 | 结果 |
|---|---|---|
| 进入节点后能否看到「上传资源」 | `node.allow_files === true` 且用户有 `resource.create`（且范围覆盖该节点） | 显示按钮 |
| 能否看到「新建文件夹」 | `node.allow_custom_folders === true` 且用户有 `directory.create_child_folder` | 显示按钮 |
| 能否看到「新建子目录」 | `node.allow_children === true` 且用户有 `directory.manage` | 显示按钮 |
| 节点是否出现在侧边栏/浏览页 | `node.enabled === true`（或该用户有 `directory.manage`） | 显示 |

**前端不得自行推断任何一条**：这些值随树一起从 `GET /api/directories/tree` 返回，
由服务端按当前用户权限过滤后计算好。前端只负责渲染"服务端说我能做什么"。

## 4. URL 形态（**已定：不可变 slug 路径**）

```
/directory/prek/virtue/teaching-resources
```

**不是** UUID 路径。

```
name = 美德        slug = virtue     URL = /directory/prek/virtue
   ↓ 管理员改名（只改 name，slug 不动）
name = 美德课程     slug = virtue     URL = /directory/prek/virtue    ← 完全不变
```

历史链接、书签、发在群里的地址，都不会因为中文名变化而失效。

规则：

1. `slug` 只能包含 `[a-z0-9-]`，长度 1–64。
2. 创建时若管理员不指定，由 `name` / `name_en` 规范化生成，**同级冲突时追加 `-2`、`-3`**。
3. **改名只改 `name` / `name_en` / `description`，绝不动 `slug`。**
4. `id` / `slug` / `parentId` **不可通过普通的"改名字"操作修改**。
   移动节点（换 `parentId`）是**独立的管理动作**；若目标父节点下已存在同名 `slug`，
   **拒绝移动并提示**，而不是自动改名（自动改名会静默让旧链接 404）。
5. `/directory/<a>/<b>/<c>` 解析失败时（某段不存在或已停用）：
   退到**最近一个仍可解析的祖先**并给出提示，**不 404、不白屏**。
6. 另提供 `/directory?id=<uuid>` 作为兜底入口，保证"不管 slug 怎么变都能到达"。

> V1 的 `code`（如 `prek:virtue`）本质上就是"路径即标识"，它带来的好处
> （URL 可读、旧地址可反解重定向）在信息架构收口时救了很多次；唯一坏处是不可编辑。
> V2 把**标识**（`slug`，冻结）与**展示**（`name`，可编辑）拆开，同时拿到两者的好处；
> 迁移时 `prek:virtue_outline` → `教育教学/prek/virtue/课程大纲` 是一对一映射。

## 5. 新增一级栏目（V2 必须支持）

业主要求的操作：

```
管理 → 目录管理 → [+ 新增一级栏目]
  名称：活动
  英文名：Activities
  说明：（可空）
  → 保存
```

结果（**不改代码、不重新发布**）：

- 侧边栏出现「活动」；
- `/directory/activities` 可访问；
- 管理员可以在其下继续建「2027 春季活动 → 春游 / 六一 / 毕业典礼」；
- 教师能看到（若其权限范围覆盖）；
- 该栏目同样是通用树节点：可以改名、改英文名、改说明、排序、停用、删除。

服务端接口：

```
POST /api/directories
{
  "parentId": null,              // null = 一级栏目
  "name": "活动",
  "nameEn": "Activities",
  "description": null,
  "slug": "activities",          // 可省略 → 自动生成
  "type": "ROOT",
  "allowChildren": true,
  "allowFiles": false,
  "allowCustomFolders": false
}
```

**与 V1 的差别**：V1 **没有**这个能力（服务端只有"在允许自建的资料夹下建子文件夹"），
所以它在 `V1_FUNCTION_MAPPING.md` 里被标为 REBUILD。V2 把它作为首要验收项：
浏览器测试 `业务流程 7：新类别` 必须真的走完"新增 → 刷新 → 教师看到"。

## 6. 子树的递归操作

| 操作 | 规则 |
|---|---|
| 读子树（浏览页） | 递归 CTE，按 `sort_order, name` 排序；停用子树对非管理员整体隐藏 |
| 读祖先链（面包屑） | 从节点沿 `parent_id` 向上，**不用 slug 前缀推断** |
| 权限范围判定 | "目标节点 ∈ 授权节点的子树" 用递归 CTE 一次判定 |
| 移动节点 | 必须拒绝"移动到自己的子树里"（否则树成环）。用祖先链检查 |
| 深度 | 硬上限 **12 层**。超过拒绝并提示（防止病态树把界面与递归查询拖垮） |
| 停用 | 停用节点自身；其子树对教师整体不可见（不需要逐个子节点写入） |

> V1 的教训：面包屑曾经用"code 前缀"推断祖先，结果 `prek:virtue_outline` 找不到
> `prek:virtue`，面包屑漏掉中间层、上传页下拉显示成 `Pre-K / 课程大纲` 重复四遍。
> V2 一律走 `parent_id`，不从前缀猜。

## 7. 改名后全站同步（验收项）

必须同步的**六处**（V1 已全部做到并被浏览器断言钉住，V2 沿用同一组验收）：

| # | 位置 | 数据来源 |
|---|---|---|
| ① | 侧边栏导航 | `DirectoryProvider.tree` |
| ② | 目录首页的卡片 | 同上 |
| ③ | 目录管理页 | 同上 |
| ④ | 上传页的「所属目录」显示 | 同上（V2 里上传页从目录进入，显示的是当前路径） |
| ⑤ | 面包屑 | 祖先链（`parent_id`） |
| ⑥ | 资源详情里的「所属目录」 | 同上 |

**实现约束**：前端只有 `client/src/directory/DirectoryProvider.tsx` 持有目录树；
任何页面不得自行 fetch 目录接口，也不得缓存自己的副本。
（V1 因此专门写了静态测试；V2 从第一天就有 `tests/no-second-directory-truth.test.mjs`。）

**缓存失效**：任何目录写操作成功后，服务端返回被影响的节点，
前端 `invalidateQueries(['directories'])` 一次，全站自动同步。
不做"局部更新"——局部更新正是"某处没同步"的来源。

## 8. 删除保护（业主 §40）

```
DELETE /api/directories/:id
  ├─ 有子节点？          → 409 DIRECTORY_HAS_CHILDREN（提示：请先删除或移动子目录）
  ├─ 有资源（含回收站）？ → 409 DIRECTORY_HAS_RESOURCES（提示：请先移动或删除资源）
  └─ 都没有            → 删除，并写审计
```

**绝不允许级联删除资源。** 数据库层用 `parent_id ON DELETE RESTRICT` 与
`resources.directory_id ON DELETE RESTRICT` 双重兜底 —— 即使服务层有 bug，
数据库也不会让一批资源随目录消失。

"移动资源"是业主 §40 提示语里的动作，所以 V2 必须提供：
`PATCH /api/resources/:id { directoryId }`（管理员可批量；
教师只能移动自己且仅在有权限的目录之间）。

## 9. 排序（业主 §41）

先做 **↑ / ↓**（只交换相邻两个节点的 `sort_order`），因为：

- 它确定性可测（一次请求后顺序必然变化，测试不需要模拟拖拽）；
- 不存在"拖到一半失败"的中间状态；
- 界面与键盘都能用。

拖拽排序作为后续增强，**但必须仍然落到同一个 `sort_order` 字段**，
不允许出现第二套顺序真相（例如 `position` 浮点数 + `sort_order` 并存）。

## 10. seed：PDF 初始目录（**已确认，严格按 PDF**）

- `database/seeds/001_directory_tree.sql`，逐字内容见 `PRODUCT_REQUIREMENTS.md` §7 与
  `DATA_MODEL.md` §12。
- **必须存在的节点**（不可自行删除）：`Pre-K 英文`、`师风师德建设`。
- **PDF 中明确标注允许自建文件夹的位置是「教学详案」与「教学资源」**，
  所以这两个节点 `allow_custom_folders = true`，其余末级资料夹为 `false`。
  （`课程大纲` / `考核评估` 不允许教师自建子文件夹。）
- `allow_files = true` 只给末级资料夹（`课程大纲` / `教学详案` / `教学资源` / `考核评估`）；
  科目层与班型层 `allow_files = false`（它们只做导航），
  这样"上传资源"按钮只会出现在真正能放文件的目录上。
- seed 与迁移分离：迁移管结构，seed 管初始内容。
- seed 是**幂等**的（按 `(parent_id, slug)` UPSERT），重复执行不产生重复节点，
  也**不会覆盖**管理员已经改过的名字（只在节点不存在时插入）。
- PDF 只是**初始**目录，不是硬编码：之后全部可改名、可增、可停用、可删（空节点）。

## 11. 浏览 UI 与管理 UI 必须分开

| | 教师（浏览） | 管理员（管理） |
|---|---|---|
| 入口 | 侧边栏 → 教育教学 / 教师成长 | 侧边栏 → 管理 → 目录管理 |
| 视觉 | **卡片**（标题 + 数量 + 简介 + 进入箭头），沿用 V1「美德」页的视觉语言 | 树 + 行内操作按钮 |
| 能看到 | 目录名、子目录卡片、资源列表 | 完整树（含停用节点）、改名/新增/删除/排序/启停/能力开关 |
| 不能看到 | 任何管理按钮 | — |

**不要把主用户体验做成数据库树。** 教师看到的是：

```
Pre-K
[ 美德 ]  [ 蒙特梭利 ]  [ 体能 ]  [ 英文 ]

点「美德」→
[ 课程大纲 ]  [ 教学详案 ]  [ 教学资源 ]  [ 考核评估 ]

点「教学资源」→ 资源列表
```

两个视图共用**同一份** `DirectoryProvider` 数据与**同一个** URL authority，
只是渲染器不同；权限判定用同一个 `directory.manage` 能力码。

## 12. 明确禁止的做法

| 禁止 | 为什么 | 防范 |
|---|---|---|
| 在 React 里写课程/栏目数组 | 这就是 V1 的"第二份真相"，改名后不同步 | `tests/no-second-directory-truth.test.mjs` |
| 为每个新栏目写一个页面组件 | 业主点名的核心问题 | 目录浏览渲染器只有一个 |
| 在路由里枚举目录路径 | 新栏目上线要改代码 | 路由用通配 `/*` 交给解析器 |
| 按 `type` 分支业务逻辑 | 会把通用树重新变成课程树 | `tests/directory-capabilities.test.mjs` |
| 直接从 `slug` 前缀推断父子关系 | V1 因此漏掉中间层 | 只用 `parent_id` |
| 用递归查询以外的办法算"子树" | 会与权限判定口径分叉 | 子树判定只有一个 SQL 片段，前后端共用它的结果 |
| `isSystem = true` 就不许改名 | 业主明确否定的旧规则 | 改名只校验 `directory.manage` + 节点存在；`id`/`slug`/`parentId` 不可改即可 |

## 13. 本模块的验收清单

1. 新建一级栏目 → 侧边栏/浏览页出现（浏览器测试，业务流程 7）。
2. 任意层级（≥4 层）可建、可浏览、可直达 URL。
3. 改中文名 → 六处同步（浏览器测试，业务流程 6）；`slug` 不变，旧 URL 仍可用。
4. 改英文名 → 切到英文界面同步；`id` / `parentId` / `slug` 不变。
5. 改说明 → 落库；清空 → 落成 `NULL`。
6. 排序 ↑↓ → 顺序持久化，刷新后保持。
7. 停用 → 教师看不到，管理员仍能看到（管理模式下有视觉标记）。
8. 自建文件夹（`allow_custom_folders`）→ 教师可建 → 刷新仍在 → 能把资源传进去（业务流程 8）。
9. 删除保护 → 有子节点/有资源时 409，且数据库层面也拒绝。
10. `allow_files = false` 的节点**不出现**上传按钮。
